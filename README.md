# payrollrti.uk

The website for [PayrollRTI](https://github.com/seatofthepants-net/payrollrti), the free Mac app that runs HMRC's Basic PAYE Tools on macOS Sequoia and later without the Terminal.

A static site: plain HTML and CSS, no JavaScript, no cookies, no tracking, and no requests to anyone else's servers. Hosted on Cloudflare Pages.

## Run it locally

```sh
node scripts/build.mjs          # builds into dist/ (Node 22, no npm install needed)
npx serve dist                  # or any static file server
```

## How it fits together

| Path | What it is |
|---|---|
| `scripts/build.mjs` | Renders every page from `data/` into `dist/`. Bakes in the latest version, the direct `.dmg` link and the download count. |
| `src/styles.css`, `src/fonts/`, `src/favicon.svg` | Styles, self-hosted Inter (OFL), icon. |
| `src/images/` | Generated by `scripts/images.py`. Committed. |
| `src/_headers` | Security headers (strict CSP), caching, `noindex` on `/stats/` and `*.pages.dev`. |
| `data/faq.json` | FAQ questions and answers. Used for both the visible FAQ and the structured data, so they can't drift apart. |
| `data/releases.json`, `data/stats.json`, `data/downloads.csv` | Written by the data Action. Don't edit by hand. |

Pages: `/`, `/releases/`, `/stats/` (unlisted), `/404.html`, plus `/llms.txt`, `/robots.txt`, `/sitemap.xml`, `/stats.json`.

## Releases and download numbers

`.github/workflows/update-data.yml` runs daily at 03:17 UTC, on demand, and whenever the app repo publishes a release (via `repository_dispatch` type `payrollrti-release`). It:

1. Reads all releases from the GitHub API and adds up `download_count` for each `.dmg`.
2. Writes `data/releases.json` and `data/stats.json`, and adds today's rows to `data/downloads.csv`. GitHub only gives running totals, so this CSV is the only record of downloads per day. Don't delete it, and don't delete old release files on GitHub (their counts go with them).
3. Commits if anything changed, then deploys.

The counts include repeat and automated downloads, so treat them as a trend. The app itself never reports anything back.

To have new releases show up immediately, the app repo needs `extras/payrollrti-notify-site.yml` copied into its `.github/workflows/` and a `SITE_DISPATCH_TOKEN` secret (a fine-grained token with Contents read/write on this repo only). Without it, new releases appear at the next daily run.

## Deploys

`.github/workflows/deploy.yml` builds and deploys to the Cloudflare Pages project `payrollrti` on every push to `main`, and after each data update. Repo secrets needed:

- `CLOUDFLARE_API_TOKEN`: Account › Cloudflare Pages › Edit
- `CLOUDFLARE_ACCOUNT_ID`

## Domains

- `payrollrti.uk` is the custom domain on the Pages project (Cloudflare DNS).
- `www.payrollrti.uk` redirects to `payrollrti.uk` with a Single Redirect rule in the `payrollrti.uk` zone. A proxied `AAAA 100::` record for `www` makes it reach Cloudflare.

## Images

```sh
pip install pillow    # 11.2+ for AVIF
python3 scripts/images.py
```

This pulls the screenshots from `docs/marketing` in the app repo and covers the HMRC crown and wordmark in the hero. The site must never show HMRC's crown or logo. If the hero screenshot changes size, the script stops: find the logo area again and check the output by eye.
